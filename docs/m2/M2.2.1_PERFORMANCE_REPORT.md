# M2.2.1 模拟生成性能

采集日期 2026-11-21（北京时间）。Intel Core i7-14650HX、Windows 11 x64 build 26200、Node.js 24.16.0。执行 `pnpm bench:simulation`，使用 Obstacle Scene、种子 42。基准以 1× 逻辑步推动生产端，将每个话题的最新帧保存在内存。点云每步推进 100 ms，默认开启 ring。相机为 160×90，RGB 和 Depth 同时订阅，每步推进 200 ms。

| 负载 | 逻辑时长 | 生成 / 送达 | 每步 P50 / P95 / 最大耗时 | RSS 峰值增量 | ArrayBuffer 峰值增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100k 点 | 30 s | 300 / 300 | 5.32 / 6.45 / 12.11 ms | 69.34 MiB | 66.38 MiB |
| 500k 点 | 10 s | 100 / 100 | 29.90 / 39.65 / 45.16 ms | 84.02 MiB | 80.11 MiB |
| 500k 点，延迟和突发 | 10 s | 100 / 141 | 30.68 / 42.70 / 51.49 ms | 80.04 MiB | 80.11 MiB |
| RGB 和 Depth | 20 s | 202 / 202 | 2.06 / 4.28 / 9.98 ms | 2.32 MiB | 2.21 MiB |

无故障的三项测试没有延迟积压。500k 故障组峰值 4 条延迟项，按负载计数 48,000,000 字节，结束时 1 条等待 80 ms 延迟窗口，溢出为 0。突发项共享源数据，但队列字节预算对每个条目单独计数。重置后四项的延迟条数、延迟字节数及保留话题数都回到 0。在事件循环让出并完成两次显式 GC 后，四项 ArrayBuffer 用量均回到预热后的基线。RSS 峰值是各组相对预热基线的增量。

这些数据衡量 Node CPU 生产步长、分配和队列。Windows Electron 冒烟另行确认 UI 能消费模拟话题。当前生产端在 Renderer 同步生成，500k 压力组的 P95 高于 30 FPS 对应的 33.3 ms 帧预算，实际绘制和交互表现需要在渲染与稳定性阶段测量。实时 GPU 100k 绘制、500k GPU 压力、30 FPS、30 分钟内存趋势及持续队列观测均待 M2.2.6 验收。原始记录位于 ``logs-root`\tests\m2-2-1-benchmark.log`。
