# M2.2.1 模拟场景

| 场景 | 标识 | 几何与运动 |
| --- | --- | --- |
| Static Room | `static-room` | 机器人固定。在 24 × 18 × 4 m 的房间中观测地面、墙、立柱和固定障碍。 |
| Moving Robot | `moving-robot` | 机器人沿可重复的解析轨迹运动，偏航随速度方向变化，场景内有运动目标。 |
| Obstacle Scene | `obstacle-scene` | 额外加入两个静态障碍和一个运动目标，机器人以较慢速度沿轨迹行驶。 |
| Noisy Sensor | `noisy-sensor` | 运动场景加入更强的 IMU 噪声和偏置，默认开启丢包和时间抖动。 |

默认种子为 42，可用范围是 0–4294967295。用相同场景、种子、传感器选项、订阅时间和故障配置从重置状态运行，可以重现相同逻辑步的消息。噪声和表面采样使用种子和步号。故障按各话题实际生成的消息计数，改变订阅时刻会改变故障触发所对应的逻辑步。

工作区支持 0.5×、1×、2×、4×。1× 以本机经过时间驱动固定步长。应用挂起或事件循环长时间阻塞时，单次定时回调最多计入 100 ms，以限制追赶负载。脚本可直接调用 `advance`，无需等待墙钟即可复现试验。每个场景可独立启动、停止和重置。

## 可控故障

| 故障 | 可重复触发规则 |
| --- | --- |
| Message Drop | 每五条省略一条，静态 TF 保持可获取。 |
| Message Delay | 每四条延迟一条，延迟 80 ms 模拟时间，静态 TF 保持即时。 |
| Timestamp Jitter | 非静态消息的采样时间交替偏移 −7 ms 和 +7 ms，同时调整消息信封和顶层 Header。 |
| TF Missing | 每三个动态 TF 样本省略一个。 |
| TF Out-of-Order | 偶数序号的动态 TF 延迟 120 ms，较新的样本可先送达。 |
| NaN Point | 每三帧复制一份点云数据，将首点的 x 置为 NaN，标记 `is_dense=false`。 |
| Invalid PointCloud Schema | 每四帧将 x 字段的偏移移到 `point_step` 之外。 |
| Sensor Disconnect | 每个 4 s 周期的 [1 s, 2 s) 撤销 RGB、Depth 和 CameraInfo，随后恢复目录和发布。 |
| Burst Messages | 非静态话题每七条中的一条送达四次，各副本具有独立信封序号。 |

故障可独立启用，也可组合。丢包在延迟和突发复制之前处理，动态 TF 上的两种延迟可叠加。延迟队列上限为 32 条及 48 MiB 批量负载，超出的延迟项计入 `queueOverflow`。全部规则只作用于模拟源。重置清空计数、缓存和队列。
