# M2.2.1 测试报告

验收日期 2026-11-21（北京时间）。环境为 Windows 11 x64 build 26200、Node.js 24.16.0、pnpm 11.28.5、Electron 45.4.1。运行使用已授权的本机。Smart App Control 读值为 0，测试过程沿用现有 Windows 安全策略。解包产物位于 ``builds-root`\m2.2.1\win-unpacked\LabScope.exe`，是未签名开发构建。

| 检查 | 结果 | 证据 |
| --- | --- | --- |
| 工作区构建、TypeScript 类型检查 | 通过 | 所有 workspace 构建、类型检查退出码均为 0。 |
| 单元与模块集成 | 通过 | 75/75，其中 55 个既有测试、18 个模拟引擎测试、2 个模拟源总线与布局测试。 |
| 场景确定性和模拟时钟 | 通过 | 四场景跨运行重现，验证启停重置、种子和倍速时间。 |
| ROS 2 Humble Schema 解码 | 通过 | 10 个话题都经过现有 CDR 写入器和解码器往返。Schema 来自 M0 捕获及 Humble 的 CameraInfo、Path、PoseStamped 定义。 |
| 点云和相机 | 通过 | 四档点数及原始字段布局，经现有 XYZ 提取器解码。验证相机像素内容、与几何相符的深度、RGB/Depth 行步长和内参。 |
| TF 数学及机器人状态 | 通过 | 父子坐标树、单位四元数、光轴方向、Odometry/Pose 一致性及有界 Path。 |
| 故障注入 | 通过 | 九种故障及延迟队列条数上限、字节上限均有断言。NaN 和坏 Schema 用例保留输入数据。 |
| 模拟工作区及 Windows Electron | 通过 | 解包版同时绑定 Viewer3D 和 CameraViewer，分别收到模拟点云和相机消息。停止保留最后一帧，重置清除模拟帧，真实会话维持 idle。 |
| M0/M1 Worker、Preload 与 IPC 回归 | 通过 | 8 项运行时测试。本地回环 Foxglove 替身使用捕获夹具，验证两类传感器的 Schema 发现、订阅引用计数、解码和断开。 |
| M2.1 工作区回归 | 通过 | Windows 解包版保存三面板及独立话题，在新 Electron 进程恢复。独立面板测试验证实时/回放和错误边界，通过原 Electron 开发运行时启动。 |

| CPU 生成及有界队列性能 | 通过 | 100k 和 500k 点短时基准，含故障队列和重置内存观察。 |
| GPU 渲染、30 FPS 与 30 分钟稳定性 | 未执行 | 分别属于后续 Viewer 和 M2.2.6 验收。 |
| 真实机器人及传感器 | 未执行 | Hardware Validation 阶段另行验证。此次没有连接真实机器人、传感器或 ROS 2 Bridge。 |

既有 `test:panel-ui` 需要 Electron 开发运行时。首次误传已封装的 LabScope 程序，测试等待外部夹具超时。改用该脚本所需的 Electron 45.4.1 开发运行时后通过。封装应用使用自身的冒烟入口，包含模拟源和回环回归。

```powershell
pnpm build
pnpm typecheck
pnpm test
pnpm test:runtime
pnpm test:integration '`builds-root`\m2.2.1\win-unpacked\LabScope.exe'
pnpm test:simulation-ui '`builds-root`\m2.2.1\win-unpacked\LabScope.exe'
pnpm test:panel-ui '<Electron 45.4.1 开发运行时的 electron.exe>'
pnpm bench:simulation
```

日志位于 ``logs-root`\tests`，包含 `m2-2-1-verification.log`、`m2-2-1-build.log`、`m2-2-1-electron.log`、`m2-2-1-panel-ui-regression.log` 和 `m2-2-1-benchmark.log`。[性能报告](M2.2_PERFORMANCE_REPORT.md)
