# LabScope M2.2 实际三维渲染性能

## 环境与方法

采集日期 2026-11-21（北京时间）。Windows 11 x64 build 26200、Intel Core i7-14650HX、NVIDIA GeForce RTX 4060 Laptop GPU（驱动 32.0.15.6624）。Windows x64 解包版使用 Electron 45.4.1、Three.js 0.187.0、ANGLE Direct3D11 WebGL2。可见测试窗口绘制缓冲区 1607 × 397。最终包从真实帧缓冲读回 10,334 个可识别点颜色像素。

短时组使用 Static Room、种子 42、1× 逻辑时钟、10 Hz 名义点云发布、单可见图层、Height 着色、2 CSS px 点径，绘制每档全量点。三路叠加另验证 30k 总点数。持续组使用相同种子的 Moving Robot、100k 点、map Fixed Frame，并同时显示动态/静态 TF、Pose、Odometry、路径和七种 Marker。

FPS 计数为 Electron 窗口中的实际 Three.js 绘制提交次数除以墙钟采样时间。帧时间列为各 0.5 秒统计窗口内的平均帧间隔的 P95。解码、处理、上传及生产列是对应窗口均值的 P95。

## 队列、工作集与稳定性

最终包四个短时组的采样窗口显示丢帧计数增量均为零。全次测试单 Viewer 队列峰值 3，来自三路叠加，每个话题一个待处理槽。500k 压力组 Renderer 工作集为 207.5 → 210.1 MiB，GPU 进程为 174.4 → 131.2 MiB。预热后几何对象数量保持 3，缓冲分配计数在组内保持 4。该组 CPU/GPU 显式点云缓冲为 11.44 / 7.63 MiB。

100k 完整场景持续 1,800.06 秒，3,576 个采样窗口均保持 100k 点、七个 TF 坐标系和七个 Marker。显示丢帧计数在采样窗口内增量为 0。Three.js 统计一直为 27 个几何和 8 个纹理，点云容量分配次数保持 4，沿用前一组的 500k 容量。收尾销毁画布和 WebGL 上下文通过。

| 30 分钟工作集 | 初值 | 峰值 | 结束 | 前 25% 中位数 | 末 25% 中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Renderer | 182.2 MiB | 219.4 MiB | 216.2 MiB | 208.4 MiB | 211.4 MiB |
| GPU 进程 | 139.2 MiB | 152.8 MiB | 132.7 MiB | 139.3 MiB | 136.8 MiB |

Renderer 首末四分之一的工作集中位数相差 3.0 MiB，GPU 中位数下降 2.5 MiB。连续采样未发现 GPU 资源数或队列持续增长。Renderer JS 堆读数为 9.5 → 40.1 MiB，包含留在 Renderer 中、供输出原始日志的 3,576 条统计样本；这项读数包含测试采样开销，不能用来单独估算应用堆增长。

长测使用独立 Windows 集成构建 `m2.2-soak`，启动时点云、相机、TF、Pose、Odometry、Path 和 Marker 已集成。随后交付构建加入本地 MCAP 文件入口、实时空间事件批传和可选轨迹长度限制。前四行短测来自最终交付包。原始数据在 ``logs-root`\tests\m2-2-full-electron.log`、`m2-2-performance-summary.jsonl` 和 `m2-2-final-gpu.log`。[验收总表](M2.2_TEST_REPORT.md) · [M2.2.2 历史性能](M2.2.2_PERFORMANCE_REPORT.md) · [M2.2.1 CPU 生产基线](M2.2.1_PERFORMANCE_REPORT.md)
